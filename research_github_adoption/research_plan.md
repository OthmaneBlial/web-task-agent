# Research plan — Web Task Agent GitHub adoption

## Main question

What does the current repository genuinely need, after its v0.5.1 productization work, to become a notably useful and recommendable open-source project with a credible path to sustained GitHub adoption?

## Subtopics

1. **Repository and product reality**
   - Inspect implemented capabilities, tests, documentation, release assets, public metadata, and the existing roadmap.
   - Separate shipped proof from planned or externally blocked work.

2. **Category and alternatives**
   - Compare the project's promise with current browser-agent, deep-research, and evidence/provenance projects using primary repositories and official documentation.
   - Identify category expectations and an ownable wedge rather than copying feature lists.

3. **Activation and distribution**
   - Evaluate clean installation, first success, shareable proof, package availability, integrations, and discoverability.
   - Identify the smallest public loops that can turn interest into use, feedback, and contribution.

4. **Trust and maintainability**
   - Review security boundaries, evaluation evidence, release provenance, compatibility, and contributor experience.
   - Define measurable acceptance gates for the next roadmap rather than vanity milestones.

## Synthesis

The final `ROADMAP.md` will prioritize dependencies and outcomes. It will keep stars as a lagging reach signal, lead with activation and retained utility, and explicitly distinguish repository work from external promotion or user-validation work.
